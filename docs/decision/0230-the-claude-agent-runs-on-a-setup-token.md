# The Claude agent runs on a setup token

Status: accepted. Adds to 0220 and 0222. For the Claude backend only, this supersedes the 0220 consequences that an SDK backend calls its provider through the model gateway and that it may lack questions, restart, steering, goals and compaction.

## Context

0220 split the runner from the agent backend and left `native` as the only backend. 0222 keeps the native agent in the control plane's built-in runner, and keeps an SDK backend on the thread's machine for the whole run, because the SDK runs its own tools in its own process.

The Claude Agent SDK authenticates with a Claude setup token (`claude setup-token`), carried as `CLAUDE_CODE_OAUTH_TOKEN`. That is a long-lived OAuth token for one person, not an API key, and not a grant from Aven's model gateway.

## Decision

- **The credential is per person.** A row in `claude_setup_tokens` holds that person's token, encrypted with `PROVIDER_ENCRYPTION_KEY` the same way a provider key is. The API returns whether one is set and its last four characters. It never returns the token, and nothing logs it. Replacing it overwrites the row. Removing it deletes the row.
- **`claude` is a backend beside `native`.** A new thread names it, and the thread keeps it, including a fork and a continuation onto another runner. The runner advertises it on `hello.backends`. Wire version stays 56: `backend` was already optional, and `claudeToken` on `run.start`, `run.resume` and `RunSecrets` is optional too. A runner from before leaves both unread. The token is sent only for a Claude run, only in memory on that run, and a reconnect carries it the same way as the run's other secrets. It is not written on the run record.
- **A Claude thread runs only when its owner has a token.** The owner is the thread's creator. A teammate driving the thread does not substitute their own token. With no token, creating the thread or starting a run throws `ClaudeTokenMissingError` (422, decision 0055): "Set a Claude setup token in Settings before this thread can run on the Claude agent".
- **The run stays on the thread's machine.** 0222 places a native run on the control plane's runner. A Claude run does not: it needs the machine for the whole run, so it goes to that runtime's runner. The control plane does not call the model gateway for it, so a missing provider key does not block it.
- **The Claude backend matches the native agent.** `question`, `restart`, `steering`, `goals` and `compaction` are all supported. The same driver prepares the run (sandbox, GitHub sign-in, OIDC workload identity, project variables, skills, the person's MCP servers, attachments, memory, cockpit, forks). The model is told to use Aven's tools. Claude Code's built-in shell and file tools are disallowed, so a command is Aven's `exec_command` (cancellable with the run), a file is Aven's, and a process the agent starts is watched the same way. `claudeModel` on `run.start` and `run.resume` is optional and does not change the wire version: it is a Claude model id (`claude-sonnet-5`, `claude-opus-4-8`, `claude-fable-5`), not a gateway model, because the setup token bills Anthropic directly.
- **Aven's tools are an MCP server the runner hosts in process**, named `aven`. It wraps the same tool list the native agent gets for that run (files, exec, git fetch, processes, ports, edit, view image, show artifact, memory, cockpit, forks, the person's MCP tools, web search, define goal, spawn agent) plus `ask_user` and `request_secret`. The SDK is not given the machine's Claude settings or an API key (`settingSources: []`, and `ANTHROPIC_API_KEY` is stripped). A project variable cannot replace the setup token. Config and session files live under the runner's journal directory (`CLAUDE_CONFIG_DIR`), not in the repository.
- **A question parks the run.** `ask_user` and `request_secret` end the run as an interaction with the same continuation the answer form already understands. While the runner process stays up, the answer is the tool result of that call and the same SDK query continues. The thread shows the card because the run is not running and the question tool is still open.
- **The thread still shows the run.** The backend maps SDK stream events (text, thinking, tool calls, tool results, usage, errors) onto Aven's run events, and files the turn through `memory.append` as ordinary messages. Text the model streams is not filed a second time. The setup token is redacted from events and from the filed transcript. The session id is stored beside the journal, without the token, and the next message resumes it. A stop such as `error_max_turns` is a distinct error: "The run used all of its turns".

A teammate's run uses the thread owner's token.                                                                                                                                                                                                          |

## Tests

`AVEN_CLAUDE_FAKE=1` on a runner selects `claudeFakeQuery` instead of the SDK. The stand-in answers one sentence and does not call Anthropic or repeat the setup token. The token is still required, still encrypted, and still handed to that runner. `e2e/claude-backend.spec.ts` saves a token in Settings, starts a Claude thread, and checks the reply. That spec records video. A runner that leaves the variable unset uses the SDK.

## Where the SDK is not the native journal

Rows marked equivalent are the closest the SDK allows. The workspace, the filed transcript and the answer form still behave as they do for native.

- A question answered after the runner process itself has gone is the next user message on the resumed session. The parked tool call lived in that process, so it cannot be completed as a tool result.
- A goal session interrupted by a restart runs again from the saved session count. There is no Anvia goal journal for a Claude query. What the interrupted session wrote stays in the workspace.
- Compaction is Claude's `/compact` on that session, which is the context that would overflow.
- A restart does not replay a tool call that was in flight. The session resumes, `CLAUDE_CODE_RESUME_INTERRUPTED_TURN` is set, and the model is told to continue.
- A subagent is a nested Claude query with the same token and the explore or general tool subset, not an Anvia agent. It cannot ask or spawn.
- The model menu is Claude's own models (`claude-sonnet-5`, `claude-opus-4-8`, `claude-fable-5`), not the person's provider catalog. The setup token bills Anthropic directly, so the run does not go through the gateway.
