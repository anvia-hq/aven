# The runner's git reads its own configuration, not the workspace's

Status: accepted. Changes how decisions 0030, 0036, 0042 and 0043 run git on the runner's host; what they do is unchanged.

## Context

A thread's workspace, `.git` included, is mounted read-write into its container, so the agent can write the repository's configuration, hooks and attributes. The runner also runs git on its own host, outside the container, against the same `.git`: marking a turn and making a thread's diff (decision 0030), listing files for the composer's `@` (0036), fetching a branch (0042) and bringing a restored workspace up to date (0043). Git runs programs its configuration names: a filter's `clean` on `git add`, its `smudge` on a checkout, a diff driver's `textconv`, hooks (`reference-transaction` runs on `update-ref`), `core.fsmonitor`, `gpg.program` when `commit.gpgSign` is set (even for `commit-tree`), and URL rewrites to other transports. Marking a turn ran `git add --all` at the start of every run, so a filter the agent planted ran on the runner's machine.

`host-git.ts` already switched off hooks, the file system monitor, credential helpers and maintenance with `-c` for the fetch and the restore. That cannot cover filters and diff drivers: their names (`filter.<name>.clean`) are the agent's to pick, and git has no switch for ignoring a repository's own configuration. Reading the names first and switching each off races an agent that can rewrite the file in between.

## Decision

- **Every git command the runner runs on a workspace goes through `hostGit`.** It points git at a directory of the runner's own (`GIT_DIR`, in the system's temporary folder, removed afterwards) whose configuration the runner writes. The configuration copies only the keys that describe the repository (`core.repositoryformatversion`, `filemode`, `symlinks`, `ignorecase`, `precomposeunicode`, `logallrefupdates`, `extensions.objectformat` and `extensions.refstorage`), and only plain values. There are no hooks, no remotes and no `info/attributes`; `info/exclude` is copied, so ignored files stay ignored.
- **Only the repository's contents are linked.** `objects`, `refs`, `packed-refs`, `logs`, `reftable` and `shallow` are symbolic links to the workspace's, so what git writes lands in the workspace as before. Nothing else of `.git` is, so a `remotes/` file or anything newer git learns to read is never seen. HEAD is copied in and put back by renaming when git moved it, since git takes a linked HEAD for no repository. A file git replaced by renaming over its link is moved back. The index is the workspace's (`GIT_INDEX_FILE`) unless the command names a scratch one.
- **An attribute that names a driver this configuration lacks does nothing.** So `.gitattributes` and filters are harmless without anything being switched off by name. The `-c` switches stay as a second line, with `commit.gpgSign=false` added; git speaks only https, or a path for tests (`protocol.allow=never`); a missing object is never fetched (`GIT_NO_LAZY_FETCH`); and the diff also passes `--no-textconv`.
- **A `.git` git cannot be pointed at safely is no repository.** That is a `.git` that is not a folder, a HEAD or configuration that is not a plain file (a link, which the runner would write through, or a pipe, which would hang it), a link anywhere git writes (a linked entry, anything under `refs` or `logs`, or a folder of `objects`), which git would write through to wherever it points, and `commondir` or `gitdir`, which would send git to a configuration elsewhere. HEAD and `info/exclude` are opened without following a link or waiting on a pipe, so they cannot be swapped for one after the check. The runner's own clones are never refused.
- **What writes the workspace's configuration on purpose still uses plain git**: the clone itself, before the agent has the workspace, and `trackPushes`, which adds a fetch refspec for the agent's own git. Writing configuration with `git config` runs nothing.

## Consequences

- Each host git command creates and removes a small directory and runs `git config --list` once more. The cost is a few milliseconds per command, `files.search` for the composer's `@` included.
- A lock git takes on HEAD or `packed-refs` is taken in the runner's directory, not the workspace's, so it does not keep out the agent's own git, or another host command, at that moment. The runner rarely writes either (a moved HEAD in a restore, `packed-refs` only when deleting a packed ref); the last write wins.
- `host-git.test.ts` plants each of these and checks that nothing ran or was written: a filter in `.gitattributes` and in `info/attributes`, a textconv, a hook, a signing program, a file system monitor, a repository nested in the workspace, a remote a missing object would be fetched from, a HEAD that is a link or a pipe, and a link out of the workspace as `refs`, under `refs` or `logs`, or as a folder of `objects`.
- Not covered: the links are looked for before git runs, so an agent that swaps one in during the few milliseconds a command runs could still have the runner write a short file (a commit id, or a compressed object) where it points. That writes a file, never runs a program.
