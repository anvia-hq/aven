# The Codex agent runs on an API key

Status: accepted. Adds to 0220, 0222 and 0242.

## Context

0242 added `claude` as a backend that runs the Claude Agent SDK on the thread's machine, on a per-person setup token, with the same capabilities as the native agent. The Codex SDK (`@openai/codex-sdk`) is the same shape of integration for OpenAI's Codex CLI: a local process, a session id, a stream of events, and tools the runner hosts. It authenticates with `CODEX_API_KEY`, an OpenAI API key, not a subscription setup token and not a grant from Aven's model gateway.

## Decision

- **The credential is per person.** A row in `codex_setup_tokens` holds that person's API key, encrypted with `PROVIDER_ENCRYPTION_KEY` the same way a Claude setup token is. Saving it accepts one line of at least 20 characters that starts with `sk-` and does not start with `sk-ant` (that prefix is a Claude token). The API returns whether one is set and its last four characters. It never returns the key. Replacing it overwrites the row. Removing it deletes the row. Settings → Codex (`/settings/codex`, `/codex-setup-token`) is the page.
- **`codex` is a backend beside `native` and `claude`.** A new thread names it, and the thread keeps it, including a fork and a continuation onto another runner. The runner advertises it on `hello.backends`. Wire version stays where it is: `codexToken`, `codexModel` and `codexEffort` on `run.start`, `run.resume` and `RunSecrets` are optional. A runner from before leaves them unread. The key is sent only for a Codex run, only in memory on that run, and a reconnect carries it the same way as the run's other secrets. It is not written on the run record.
- **A Codex thread runs on its creator's key.** Creating the thread checks the creator. Every later start, answer and compaction loads `thread.createdBy`'s key, including when a teammate is driving. A missing key throws `CodexTokenMissingError` (422): "Set a Codex API key in Settings before this thread can run on the Codex agent".
- **The run stays on the thread's machine.** The same placement as Claude: a native run may use the control plane's runner; a Codex run goes to the thread's runtime and does not ask the model gateway.
- **The package mirrors `@aven/claude`.** `@aven/codex` holds the backend, the event mapping, the sessions database, the goal loop, the tool host and a fake query (`AVEN_CODEX_FAKE=1`). `openAgentBackends` registers `CodexRuns` next to `ClaudeRuns`. The driver prepares a Codex run with the same `hostedInput` path as Claude (`codexInput`): sandbox, GitHub sign-in, workload identity, project variables, skills, MCP servers, attachments, memory, cockpit and forks.
- **Models.** `@aven/protocol/codex-models` lists `default` and `astra` (`gpt-6-astra`, 272k), `sol` (`gpt-6.1-sol`, 272k), `terra` (`gpt-6.1-terra`, 500k) and `luna` (`gpt-6-luna`, 272k). Efforts are `low`, `medium`, `high`, `xhigh`, `max` and `ultra`. The menu default effort is `medium`. The CLI's own default for Astra is `low`; the menu pins `medium` so the slider matches Claude. `minimal` and `persistent` are not offered.

## Parity with the Claude backend

| Claude capability                                                        | Codex equivalent                                                                                                                                                                                                               | Gap                                                                                                                                                                                                                                                     |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Setup token, encrypted per person                                        | OpenAI API key, same table shape and Settings page                                                                                                                                                                             | No `claude setup-token` flow. The person creates a key at platform.openai.com/api-keys.                                                                                                                                                                 |
| In-process MCP (`createSdkMcpServer`)                                    | Local HTTP JSON-RPC server (`serveCodexMcp`) the CLI is configured to call. Each run mints a bearer token in `AVEN_CODEX_MCP_TOKEN` (`bearer_token_env_var`) and refuses a request with the wrong token or a browser `Origin`. | The SDK has no in-process MCP. The server speaks `initialize`, `ping`, `tools/list` and `tools/call`. A notification with no id is answered `202`. GET returns a short SSE and closes.                                                                  |
| Built-in tools denied (`CLAUDE_DISALLOWED_TOOLS`, `bypassPermissions`)   | `features.shell_tool = false`, sandbox `read-only`, approval `never`, web search `disabled`                                                                                                                                    | There is no denylist of tool names. If the CLI still emits `command_execution`, `file_change` or `todo_list`, those events are mapped onto `exec_command`, `apply_patch` and `todo`.                                                                    |
| Long-lived prompt stream; steers inject into the next tool result        | One `runStreamed` per turn. A steer during a turn is injected into the next MCP tool result (`steered()`). A steer left at the end of a turn is the next turn.                                                                 | The SDK writes stdin once and closes it, so a turn cannot stay open for a later prompt.                                                                                                                                                                 |
| `ask_user` / `request_secret` park the run                               | Same park, same continuation, same answer form                                                                                                                                                                                 | An answer after this process has exited resumes the session with the answer as the next user message. There is no `CLAUDE_CODE_RESUME_INTERRUPTED_TURN`. Rejoin sends the same continue sentence on `resumeThread`.                                     |
| `/compact`, or a note when there is no session                           | No session: the same `NOTHING_TO_COMPACT` note. A session: a summary turn (`COMPACT_TURN`)                                                                                                                                     | `codex exec` does not honor slash commands, so this does not rewrite the session the way `/compact` does. The model still compacts on its own when the context fills.                                                                                   |
| System prompt appended to the preset                                     | `AVEN_NOTE` plus the run instructions are prefixed onto the first user turn only                                                                                                                                               | The SDK has no system-prompt append. A resumed turn is the prompt alone.                                                                                                                                                                                |
| Images as base64 content blocks                                          | Written under `CODEX_HOME/images` and passed as `local_image` paths                                                                                                                                                            | Steering images are still MCP image content blocks, as on Claude.                                                                                                                                                                                       |
| Usage plus the model's context window from the SDK                       | Usage maps `input_tokens`, `output_tokens`, `cached_input_tokens` and `cache_write_input_tokens`. The window comes from the menu catalog (`codexContextOf` on the alias)                                                       | The SDK does not report a context window. `reasoning_output_tokens` is not added on top of `output_tokens`.                                                                                                                                             |
| `error_max_turns` → "The run used all of its turns"                      | `turn.failed` and `error` become the run error. An auth-shaped message becomes "The Codex API key was rejected. Replace it in Settings."                                                                                       | There is no max-turns knob, so that stop is not synthesized.                                                                                                                                                                                            |
| Subscription `limits` events and the limits card                         | Not sent                                                                                                                                                                                                                       | The SDK has no plan-limits event. The limits card stays Claude-only.                                                                                                                                                                                    |
| CLI downloaded on first run and checked against a manifest               | The CLI shipped by `@openai/codex` (the SDK's optional dependency), or `CODEX_PATH`                                                                                                                                            | A compiled `aven-runtime` cannot resolve the CLI from `node_modules` unless `CODEX_PATH` is set. There is no download-on-first-run. A missing CLI is reported as "The Codex CLI could not be found…".                                                   |
| Subagents as nested queries                                              | A nested Codex thread, questions and children off                                                                                                                                                                              | Same shape as Claude's nested query.                                                                                                                                                                                                                    |
| Goals, steering, cancellation, redaction, filing through `memory.append` | The same driver and the same goal loop (`runCodexGoal`)                                                                                                                                                                        | Session files live under the runner's journal (`CODEX_HOME` is `join(home, "codex", threadId)`), not in the repository. Project variables whose names start with `OPENAI_` or `CODEX_` are dropped, then the run sets `CODEX_API_KEY` and `CODEX_HOME`. |

## Consequences

- A runner that offers `codex` must be able to spawn the Codex CLI. Tests and the e2e spec set `AVEN_CODEX_FAKE=1` and never do.
- The menu alias, not the resolved slug, is what `CodexTurn` uses for the context window. Passing `gpt-6.1-terra` as the model id would fall through to Astra's window, so the wire carries the alias (`terra`).
